# semantic-similarity-llm-eval

This repository is a Python research pipeline for evaluating whether semantic
similarity in embedding latent space can serve as a proxy for LLM QA prediction
correctness.

The project covers short-form and long-form QA. It generates LLM predictions,
creates automatic correctness labels, computes embedding similarity between
predictions and references, evaluates similarity as a classifier score, and
exports tables, figures, failure cases, and Part 4 failure-analysis reports.

## Key Points

- The evaluation label is generated by code as `correct_label`; it is not a
  human annotation. See `src/correctness_labeling.py`.
- Raw teacher-provided answers are stored as `correct_answer` in
  `data/raw/*/merged_fb.json` and are loaded as `ground_truth`.
- `project.auto_paths: true` makes paths derive from `data.dataset` and
  `data.sample_size`, preventing mixed dataset/result folders.
- `project.preserve_runs: true` writes similarity and evaluation artifacts
  under run-specific directories instead of overwriting prior experiments.

## Repository Layout

```text
.
  config.yaml
  requirements.txt
  README.md
  data/
    raw/                         # teacher-provided source QA data
    interim/
      predictions/               # generated LLM predictions
      similarity/                # fixed-path similarity artifacts
  outputs/
    experiments/results_*/       # metrics, figures, failure cases, run outputs
    analysis/failures_analysis_and_improvement/
                                  # Part 4 summary tables, figures, reports
  scripts/
    pipeline/                    # runnable main pipeline entry points
    analysis/                    # runnable analysis/report entry points
  src/                           # reusable implementation modules
  tests/                         # unit tests
  docs/                          # structure docs, onboarding, plans, references
```

`src/` contains reusable implementation logic. `scripts/` contains command-line
entry points that orchestrate the pipeline by calling `src/` modules.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Prediction generation uses the configured OpenAI-compatible Qwen/DashScope
client. For real LLM prediction runs, set:

```bash
export DASHSCOPE_API_KEY=...
```

Evaluation, visualization, and Part 4 analysis can run from existing generated
artifacts without calling the LLM API.

## Configuration

Edit `config.yaml`. For most runs, only these fields need changing:

```yaml
data:
  dataset: sciq              # sciq / simple_questions_wiki / nq / truthfulQA
  sample_size: 500           # use a small number for tests, null for full data
project:
  auto_paths: true
  preserve_runs: true
  run_id: auto
```

With `auto_paths: true`, paths resolve to this pattern:

```text
data/raw/{dataset}/merged_fb.json
data/interim/predictions/{dataset}_{llm_run_name}_predictions_{sample_size}.jsonl
outputs/experiments/results_{dataset}_{sample_size}/runs/{run_id}/similarity/{dataset}_{llm_run_name}_similarity_{sample_size}.jsonl
outputs/experiments/results_{dataset}_{sample_size}/runs/{run_id}/tables/
outputs/experiments/results_{dataset}_{sample_size}/runs/{run_id}/failure_cases/
outputs/experiments/results_{dataset}_{sample_size}/runs/{run_id}/figures/
```

When `run_id: auto`, `02_compute_similarity.py` creates a timestamped run and
writes `latest_run_id.txt` in the corresponding result directory. Evaluation
and visualization read that latest run by default. Set `project.run_id` to a
fixed value when you intentionally want a reproducible named run.

## Main Pipeline

Run commands from the repository root.

1. Generate LLM predictions:

```bash
python scripts/pipeline/01_generate_predictions.py
```

2. Prepare references, label correctness, and compute similarity scores:

```bash
python scripts/pipeline/02_compute_similarity.py
```

3. Evaluate similarity as a correctness classifier:

```bash
python scripts/pipeline/03_evaluate.py
```

4. Generate plots:

```bash
python scripts/pipeline/04_visualize_results.py
```

There are no legacy script entry points in the top-level `scripts/` directory;
use the explicit `scripts/pipeline/` and `scripts/analysis/` paths.

## Part 4 Failure Analysis

To rebuild the failure-analysis summary tables, figures, and reports from
existing experiment outputs:

```bash
python scripts/analysis/analyze_part4_strict.py
```

Outputs are written to:

```text
outputs/analysis/failures_analysis_and_improvement/
  summary_tables/
  figures/
  part4_report.md
  part4_report.zh.md
```

The script reads baseline and improvement results from
`outputs/experiments/results_*`, including the NQ multi-view runs under
`outputs/experiments/results_nq_500/runs/`.

## Core Modules

| Module | Responsibility |
| --- | --- |
| `src/data_loader.py` | Load teacher-provided QA data and create project records. |
| `src/generate_predictions.py` | Create LLM clients and generate predictions. |
| `src/correctness_labeling.py` | Compute automatic correctness labels. |
| `src/reference_answer.py` | Extract focused NQ references from long evidence passages. |
| `src/answer_span.py` | Extract answer spans from prediction text. |
| `src/compute_embeddings.py` | Wrap sentence-transformers embedding models. |
| `src/compute_similarity.py` | Compute cosine and blended similarity fields. |
| `src/sentence_level_similarity.py` | Compute sentence-level max similarity. |
| `src/multi_view_similarity.py` | Compute span-level and multi-view similarity scores. |
| `src/entity_overlap.py` | Compute overlap and hybrid lexical/embedding scores. |
| `src/factual_units.py` | Extract dates, numbers, entities, and factual conflicts. |
| `src/evaluate.py` | Compute metrics, thresholds, ablations, and failure cases. |
| `src/visualize.py` | Generate ROC, PR, distribution, and correlation plots. |
| `src/utils.py` | Resolve config paths, run IDs, JSON/JSONL I/O, and validation. |

## Outputs

Important generated files include:

- `evaluation_results.csv`: main embedding-similarity metrics.
- `baseline_ablation_results.csv`: exact match, containment, token F1, overlap,
  embedding, hybrid, and multi-view comparisons.
- `multi_view_ablation_results.csv`: NQ multi-view ablation subset.
- `question_type_metrics.csv`: question-type-aware threshold results.
- `case_studies.csv`: representative examples for reports.
- `failure_cases/*.jsonl`: high-similarity wrong and low-similarity correct
  records per embedding model.
- `run_metadata.json`: resolved dataset, paths, run ID, LLM, and embedding
  model metadata.
